# 轻量桌宠 V1 功能清单与开发方案

> 本文是 V1 目标方案，不等于 0.2.0 当前功能。当前交付已完成离线桌宠与 18 组动画，尚未接入本文 Gate 3 的 AI 对话；实际状态见 `lightpet-acceptance-report.md`。

状态：需求范围已确认，可以进入技术原型开发。

## 1. 产品定义

这是一个 Windows 10/11 x64 平台的轻量桌宠。

产品第一身份是桌宠，AI 是由用户主动调用的可选对话能力。没有配置 AI、网络断开或服务不可用时，除 AI 对话外的全部功能仍应正常工作。

第一版先供内部使用，但工程结构、角色包格式和异常处理应允许以后公开发布。宿主程序计划开源，角色美术、角色人格内容和商业服务可以独立管理。

## 2. V1 功能清单

### 2.1 桌宠宿主

- 透明、无边框、置顶窗口。
- Windows 10/11 x64。
- 单实例运行，同一时间只启用一只宠物。
- 支持鼠标拖动，并记住上次位置。
- 支持多显示器；角色可被拖到其他显示器并记住位置。
- 自主活动只沿当前水平线左右行走，不自行在整个屏幕上下乱跑。
- 默认采用活泼行为：约每 8–20 秒触发一次观察、短距离行走或小动作。
- 支持交互模式与点击穿透模式切换。
- 桌宠始终显示；首版不自动检测全屏应用。
- 关闭对话面板不退出桌宠；程序只能通过托盘菜单明确退出。
- 支持开机启动，但默认关闭。

### 2.2 鼠标交互

- 单击头部：摸头反馈。
- 单击躯干：摸身体反馈。
- 在头部按住约 500ms：长按/捏脸反馈。
- 拖动超过约 5–8 像素：进入提起/拖动状态，不再触发单击。
- 松开：播放下落/落地动画。
- 双击角色：打开或关闭 AI 对话面板。
- 右键角色：打开简化菜单。

### 2.3 18 组正式动画

| # | 动作组 | 主要触发 |
|---|---|---|
| 1 | 基础待机 | 无其他任务时循环 |
| 2 | 随机观察 | 自主行为调度 |
| 3 | 左右行走 | 自主闲逛 |
| 4 | 提起/拖动 | 鼠标拖动 |
| 5 | 下落/落地 | 松开角色 |
| 6 | 摸头 | 单击头部 |
| 7 | 摸身体 | 单击躯干 |
| 8 | 长按/捏脸 | 头部长按 |
| 9 | 启动登场 | 程序启动 |
| 10 | 退出离场 | 用户退出 |
| 11 | 睡觉 | 长时间无交互 |
| 12 | 思考 | AI 请求刚提交 |
| 13 | 说话 | AI 流式输出 |
| 14 | 开心 | 本地规则或 AI 白名单情绪 |
| 15 | 难过 | 本地规则或 AI 白名单情绪 |
| 16 | 惊讶 | 本地规则或 AI 白名单情绪 |
| 17 | 专注处理 | AI 首个响应等待较久 |
| 18 | 挥手问候 | 打开对话面板或本地问候 |

每组动作按需要使用 `A_Start / B_Loop / C_End` 三阶段，不强迫所有动作采用相同帧数。动作必须完整，不能以重复帧或低质量占位图凑满 18 组。

### 2.4 本地台词系统

- 普通交互完全由本地规则和角色包台词驱动，不调用 LLM。
- 场景至少包括：启动、退出、随机待机、摸头、摸身体、长按、拖动、落地、睡觉、唤醒、打开对话和错误提示。
- 每个场景可配置多条台词、选择权重和冷却时间。
- 可以偶尔主动显示本地台词，默认间隔约 3–8 分钟，并允许关闭。
- 本地台词不依赖网络，也不产生 API 费用。

### 2.5 AI 对话

- 只有用户在对话面板中按下发送，程序才允许发起 API 请求。
- 双击角色和打开对话面板本身不调用 LLM。
- 第一版只支持文字输入，不支持图片、截图、语音或 TTS。
- 使用通用 OpenAI-compatible HTTP 接口，可配置接口地址、模型和 API Key。
- 回答采用流式输出。
- 对话气泡附着在角色旁边，靠近屏幕边缘时自动翻转方向。
- 气泡可以展开，但不变成独立聊天软件主窗口。
- 面板打开期间允许连续对话；关闭面板立即清空上下文。
- 不在磁盘保存对话历史。
- AI 只能从宿主白名单选择情绪或动作，不能自由执行动画名、系统命令、文件操作或程序操作。
- AI 返回格式错误时只显示可用文字，不执行任何未知动作。
- API Key 使用 Windows DPAPI 加密；允许选择不保存 Key。
- 网络错误、超时或余额问题只影响当前对话，桌宠立即恢复本地待机。

### 2.6 对话显示

- 支持纯文本选择和复制。
- 支持简单链接；打开外部链接前必须确认。
- 不引入 WebView 或完整 Markdown/HTML 渲染器。
- 不支持图片、表格、复杂代码块或嵌入网页。

### 2.7 设置与托盘

V1 设置严格限制为：

- 当前角色。
- 显示大小：默认约 260，允许约 160–400。
- 不透明度。
- 自主活动开关。
- 本地主动台词开关。
- 点击穿透及切换快捷键。
- 开机启动。
- AI 接口地址、模型、API Key 和是否保存 Key。
- 清除当前对话。
- 打开角色包目录。
- 打开日志目录。
- 退出程序。

不提供皮肤编辑器、动画编辑器、在线商店、主题系统或复杂调试面板。

### 2.8 角色包

- 角色包放置在 `pets/` 目录。
- 设置界面可以扫描并切换合法角色包，无需重启整个程序。
- 角色包只允许包含图片、可选本地声音目录、JSON 配置、本地台词和角色人格文本。
- V1 宿主不播放声音，但格式可以保留未来兼容字段。
- 角色包不能包含或执行脚本、DLL 和外部程序。
- 切换角色时释放旧角色图像资源，只保留当前角色必要资源。
- 非法、缺帧、越界或格式错误的角色包必须被拒绝，不能导致宿主崩溃。

### 2.9 日志与隐私

- 不上传遥测、崩溃信息或使用统计。
- 本地使用滚动日志，限制文件数量与总大小。
- 日志不得记录 API Key、Authorization 请求头或完整对话内容。
- 用户可以直接打开并删除日志目录。

## 3. 明确不做

- 饥饿、健康、心情数值、等级、经验、金币等养成系统。
- 商店、物品、成就、工作计时和任务系统。
- Steam、创意工坊和在线角色商店。
- 多只宠物同时运行及宠物间互动。
- 第三方脚本、DLL 插件和角色包代码执行。
- AI 自动发言、自动联网、后台观察桌面或监听剪贴板。
- 文件读取、程序控制、系统命令、工具调用和 Agent 能力。
- 持久化对话记忆、向量数据库或人物长期记忆。
- 图片、截图、语音输入、语音识别和 TTS。
- 内嵌浏览器和完整 Markdown 渲染。
- 第一版安装程序、在线更新和自动更新。
- 第一版 macOS、Linux、Windows ARM 支持。

## 4. 技术方案

### 4.1 技术栈

- C# / .NET 10 LTS（使用工作区现有 SDK）。
- WPF，Windows x64。
- Framework-dependent 发布，避免捆绑完整 .NET 运行时。
- 使用 WPF 原生图像和窗口能力，不引入 Electron、WebView、SkiaSharp 或大型 UI 组件库。
- 设置使用小型 JSON 文件，不引入数据库。
- AI 使用原生 `HttpClient` 和流式响应，不引入厂商 SDK。

### 4.2 工程模块

```text
LightPet.sln
├─ LightPet.App          # WPF 窗口、托盘、设置、对话气泡
├─ LightPet.Core         # 状态机、行为调度、交互、动作切换
├─ LightPet.Animation    # 帧播放、A/B/C 阶段、锚点、缓存
├─ LightPet.Packs        # 角色包读取、校验、切换
├─ LightPet.Dialogue     # 本地台词、权重、冷却时间
├─ LightPet.AI           # 可选 OpenAI-compatible 客户端
└─ LightPet.Tests        # 状态机、包校验、AI 格式与性能测试
```

AI 模块只能被明确的“发送消息”命令调用。桌宠核心不得反向依赖 AI 模块。

### 4.3 动画资源策略

- 每帧包含持续时间、身体锚点和可选点击区域。
- 固定脚底/骨盆锚点，禁止按每帧外轮廓重新居中。
- 每个动作独立按需加载；不在启动时解码全部 18 组动画。
- 当前动作和下一动作可以预加载，完成后通过小型 LRU 缓存回收。
- 左右行走可以共享时序，但角色存在非对称标记时不得直接整体镜像。
- 角色包校验必须检查透明度、画布、边距、锚点漂移、帧时长和阶段完整性。

## 5. 三道开发验收门

### Gate 1：轻量技术原型

范围：

- 透明置顶窗口。
- 单实例和托盘退出。
- 待机、左右行走、摸头三组标杆动画。
- 不等帧时长和 A/B/C 状态机。
- 固定骨盆/脚底锚点。
- 拖动、点击区域和位置记忆。
- 基础性能监测。

通过条件：

- 角色没有可见的非设计性平移、尺寸跳变或裁剪。
- 原型工作集不超过 200MB。
- 空闲 CPU 平均不超过 3%。
- 未配置 AI 时不产生网络连接。
- 连续运行和重复切换动作不持续增长内存。

Gate 1 未通过时，不制作其余 15 组动画，也不开发 AI。

### Gate 2：完整离线桌宠

范围：

- 完成并接入全部 18 组动画。
- 自主行为调度。
- 全部鼠标交互。
- 本地台词系统。
- 睡觉、唤醒、启动和退出流程。
- 点击穿透、设置、托盘和角色包切换。
- 角色包格式与自动校验。

通过条件：

- 关闭 AI 后仍是完整可用的桌宠。
- 18 组动作全部存在真实触发路径。
- 所有动作通过视觉 QA、边距、锚点和阶段检查。
- 角色包异常不会导致宿主崩溃。
- 切换角色后旧资源被释放。

### Gate 3：AI 与可交付 MVP

范围：

- 附着式对话气泡和展开面板。
- OpenAI-compatible 配置。
- 流式文字回答。
- 对话期间白名单情绪和动作。
- DPAPI Key 保存。
- 超时、取消、错误恢复。
- 本地滚动日志。
- 绿色便携版 ZIP。

通过条件：

- 只有用户点击发送才会联网。
- 关闭面板后上下文被清空，磁盘不存在对话历史。
- 恶意或格式错误的模型输出不能执行未知动作。
- AI 故障不会影响离线桌宠状态机。
- 便携包在干净环境完成启动、互动、AI 配置与退出流程。

## 6. 动画质量验收标准

- 待机骨盆锚点在最终显示尺寸下非设计性漂移不超过约 1 像素。
- 脚底基线在非跳跃、非下落动作中保持稳定。
- 相邻帧不得出现明显尺寸跳变；呼吸造成的变化必须连续且幅度克制。
- 所有身体部分必须保留安全边距，不能把已经裁掉的源图重新居中冒充合格。
- 待机动作必须使用缓入缓出和不等帧时长，不允许快速等间隔鬼畜循环。
- 行走必须包含起步、交替步态和收步，左右方向必须正确。
- 交互动作必须有预备、主要反应和恢复，不能直接从待机跳到极端姿势。
- 每个动作必须生成逐帧接触表和实际速度预览，由视觉检查确认后才进入角色包。

## 7. 性能策略

原型阶段采用宽松但明确的阻断线：

- 工作集小于 200MB。
- 空闲 CPU 平均小于 3%。
- 不允许无上限增长的缓存。

完整 MVP 再以以下目标优化，但不阻塞最早期原型：

- 空闲工作集目标小于 100MB。
- 空闲 CPU 目标小于 1%。
- 冷启动到角色出现目标小于 1.5 秒。
- 宿主程序不含角色资源目标小于 20MB。
- 单角色便携包目标小于 80MB。

## 8. 实际开发顺序

1. 创建全新轻量解决方案，不在 VPet 工程内删改。
2. 实现透明窗口、单实例、托盘和位置保存。
3. 实现角色包最小格式与严格校验。
4. 实现按帧时长播放、A/B/C 状态机和固定锚点。
5. 接入待机、左右行走、摸头三组标杆动画。
6. 完成 Gate 1 性能与视觉验收。
7. 实现鼠标区域、拖动、落地和自主行为调度。
8. 实现本地台词系统。
9. 制作并验收其余 15 组动画。
10. 实现设置、点击穿透和角色热切换。
11. 完成 Gate 2 离线桌宠验收。
12. 实现附着式 AI 对话面板和流式客户端。
13. 实现白名单动作、DPAPI、取消和错误恢复。
14. 完成 Gate 3，并生成绿色便携版。

## 9. 开工条件

本文件即 V1 范围基线。后续新增功能必须明确说明进入 V1、V1 后续版本或不做；不能在开发过程中无声扩张范围。

下一步从 Gate 1 开始，先创建独立解决方案和最小角色包协议，不改造 VPet 主程序。
