# Cue 刘海动画修正 · 2026-09-05

用户反馈上一版展开/收回生硬、掉帧。旧实现直接动画 `Window.Width/Height`，并在 `SizeChanged` 调用 `SetWindowPos`，Viewbox 内的按钮随窗口重新分配空间；反向会重置进度与透明度。

## 修正

- 起点一次准备完整宿主，动画中不改变原生窗口尺寸或位置。
- 工具以最终尺寸布局，用缓存复用静态绘制；只改变外部圆角裁剪区域和淡入淡出，不缩放文字/图标。
- 使用解析临界阻尼矩形动画；反向从同一个 WPF AnimationClock 读取当前速度，保留位置和速度。
- 结束后缩小真实 HWND，隐藏过程中也强制结算，防止残留透明大窗口。裁剪区外的原生鼠标命中检查通过。
- 标注模式切换也保持旧/新布局所需的最大宿主宽度，收敛后再回收；底部工具栏收起先淡出，再恢复贴顶入口。

## 证据

命令：`dotnet run --project src/Cue.Diagnostics -c Release -- --toolbar-motion`

| 指标 | 旧版 | 新版 |
| --- | ---: | ---: |
| 完整展开/收回次数 | 16 | 16 |
| 原生窗口变动通知 | 266 | 48（只在边界调整） |
| 绘制回调间隔中位数 | 16.7548ms | 6.3018ms |
| 绘制回调间隔 P95 | 33.3667ms | 18.1599ms |
| 工具内容 Measure 次数 | 未细分 | 0 |
| 工具内容 Arrange 次数 | 未细分 | 32（起止边界） |

这是本机 WPF 回调/布局计数，不是最终显示帧率，也不是严格受控的 GPU 帧呈现基准。旧版动画200ms，每次观察300ms；新版420ms，每次观察470ms，均覆盖完成阶段。`LayoutUpdated` 只是全局布局通知，不等于按钮重新测量/排列，因此新探针另行包裹工具内容统计 Measure/Arrange，不以通知数量作重排结论。

`--toolbar` 检查：小刘海原生尺寸、展开/收起、自动收起、隐藏时结算、快速反向、解析速度连续、动画中 HWND 边界保持不动而裁剪变化、透明区域鼠标穿透。`--annotation` 全流程回归通过（绘制、历史、文字、冻结、导出、桌面操作和会话保留）。
